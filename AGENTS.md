# AGENTS.md

Notes for anyone, human or AI agent, changing this code. `README.md` covers playing the game, its controls and
what the tests check; this file covers how the code is put together and the rules that keep it working.

## What this is

A paper-round game in the style of Atari's 1985 arcade game Paperboy, in C# on .NET 10 and Avalonia 12, drawn
through Avalonia's `DrawingContext`. One self-contained executable per platform (Windows, macOS and Linux, x64 and ARM). Everything in
it is original: the graphics are drawn in code, and the sounds and tunes are synthesised by
`tools/make_sounds.py`.

## Commands

```bash
dotnet build AVAPaperboy.slnx                     # the SDK version is in global.json (10.0.400 or later)
dotnet test AVAPaperboy.slnx                      # every test runs headless: no window opens
dotnet run --project src/AVAPaperboy              # play it; --no-audio for silence
PAPERBOY_SHOTS=$PWD/Images dotnet test tests/AVAPaperboy.Tests --filter ScreenshotTests   # refresh the README's pictures
PAPERBOY_PROBE=1 dotnet test tests/AVAPaperboy.Tests --filter PaperboyProbe   # how the computer rider fares, for tuning
python3 tools/make_sounds.py                      # rebuild src/AVAPaperboy/Sounds (standard-library Python only)
```

`Directory.Build.props` sets `TreatWarningsAsErrors`, nullable reference types and implicit usings for every
project: a warning fails the build, so keep it at zero.

## Layout

- `src/AVAPaperboy/Engine/`: the game, with no Avalonia drawing in it.
  - `GameEngine.cs` runs the states (title, attract, play, pause, game over, initials, high scores) and the
    fixed-step loop.
  - `GameEngine.Play.cs` plays a day: the bike, the papers, deliveries and cancellations, the things in the way,
    and the training ground.
  - `Street.cs` lays out Larkspur Lane: twenty houses, and the hazards for each day of the week.
  - `Geometry.cs` has the street's measures and projection (`Field`).
  - `Entities.cs` has `Controls`, the rider, papers, houses and things.
  - `RiderPilot.cs` is the computer paperboy, used by the attract mode and the tests.
  - `InputHandler.cs` (keys) and `ControllerManager.cs` (SDL2 gamepads) produce `Controls`.
  - `HighScoreTable.cs`, `InitialsEntry.cs` and `SoundManager.cs` do what their names say.
- `src/AVAPaperboy/Views/`: `GameCanvas` (split over two partial files) draws the 1024x768 frame and runs the
  60 Hz timer.
- `src/AVAPaperboy/Audio/`: the OpenAL Soft audio engine, shared with the author's other AVA games.
- `src/AVAPaperboy/Sounds/`: the WAV files the game plays, generated by `tools/make_sounds.py`.
- `tests/AVAPaperboy.Tests/`: xUnit v3 with `Avalonia.Headless.XUnit`: `GameplayTests`, `ScreenshotTests` and
  the opt-in `PaperboyProbe`.

## Rules that keep it working

- **Fixed steps.** `GameEngine.Update` advances the game in fixed 1/60 s steps (`Field.Step`), independent of the
  frame rate, so a seed always plays the same game. Draw random numbers from the engine's seeded `_rng` (a
  `Random` made from the game's seed), never from `Random.Shared`.
- **Engine first, drawing second.** Gameplay belongs in `Engine/`, where tests can reach it without a window.
  `Views/` only reads the engine and draws it.
- **Input goes through `InputHandler`.** Up/down on keys and stick must produce the same `dy` sign the engine
  expects: negative (up the screen) rides faster, positive slower. Test new controls through `InputHandler`, not
  by setting `Controls` directly.
- **SDL under one lock.** `ControllerManager` starts, polls and stops SDL only inside `lock (Sdl)`. The tests
  create many handlers in parallel, and unlocked SDL calls corrupt its heap.
- **Audio.** OpenAL Soft through Silk.NET. `Directory.Build.targets` swaps in the official Windows `soft_oal.dll`
  from `Audio/native/`, which needs no Visual C++ runtime. In a virtual machine `OpenAlConfig` writes a larger
  mixing period to `ALSOFT_CONF` so the sound doesn't break up.
- **Tests never touch the player's files.** High scores live in the app-data folder (`AVAPaperboy`); tests load
  the table from a temporary folder and run silent (`Silent = true`). `Calm = true` stops the traffic (cars and
  skaters) turning up, for tests that need a quiet ride.

## Making a change

- Add or update tests with every gameplay change. `dotnet test` must pass, with no warnings.
- If the change shows on screen, refresh the screenshots with the command above, and look at them.
- Update `README.md` (features, controls, the test list) to match.
- New sounds go into `tools/make_sounds.py`, not as hand-edited WAV files.

## CI and releases

`.github/workflows/build.yml` builds and tests every push. It then publishes self-contained single-file builds for
win-x64/x86/arm64, linux-x64/arm64/arm and osx-x64/arm64. Every run keeps the builds as workflow artifacts.
Only pushes to `main` replace the assets of the `latest` pre-release, and a `v*` tag makes a proper release.
A release run then asks the portfolio site to rebuild, if the `SITE_REFRESH_TOKEN` secret is set.
